# Design

## Context

见 proposal.md。收尾检查发现 `tests/exam.test.cjs` 及 `npm test` 已用于本地演示逻辑，尚无 PostgreSQL、接口、安全或完整端到端测试。本 change 扩展为平台验证体系，保留有用的演示用例并逐项核对目标契约；前端自动计分用例不能证明服务端自行批改正确。所有 scenario 编号是稳定来源，reference 的“50／100 ms”明确是示例，本提案采用相称的阈值。

## Goals / Non-Goals

**Goals:** 用真实 PostgreSQL 验证关键一致性；隔离外部依赖；场景可追溯；让业务成功信号、协议错误与副作用检查彼此清楚。

**Non-Goals:** 不堆砌只测形状的用例，不把所有失败路径变成浏览器端到端，不因缺真实前端而用原型制造集成通过记录，不在本次 propose 阶段运行不存在的应用测试。

## Decisions

### 1. 三层测试与独立证据

使用与拟议 TypeScript 后端匹配的单元／接口运行器，以及浏览器端到端运行器；具体工具版本在测试基础任务中锁定并接受安全扫描。单元测试注入时钟与仓储端口；接口测试启动真实后端和独立 PostgreSQL；端到端连接真实前端、后端和测试库。

| 层次 | 覆盖 | 数据与替身 | 主要断言 |
| --- | --- | --- | --- |
| 单元 | 时间区间、评分范围、状态机、归属规则 | 合成数据、注入时钟 | 精确结果、拒绝原因、禁止副作用 |
| 接口 | 每条业务资源的正常、失败、边界；并发、幂等、授权 | 真实 PostgreSQL；文件与通知适配器替身 | code、字段、数据库状态和事件数 |
| 端到端 | 学生注册→考试→批改→错题；管理员创编→发布任务→发送消息→查看已读 | 真实应用，合成账号和题目 | 页面反馈及最终业务结果 |
| 人工／工具检查 | 设计四态、键盘、对比度、备份恢复、许可证 | 原型或指定环境实测 | 场景证据和具名复核 |

测试按 `tests/<layer>/<normal|failure|boundary>/` 组织。产品设计阶段以原型走查满足设计交付，真实 UI 行为留给前端实现集成，不把暂缺集成当跳过测试绿色。

### 2. 追溯矩阵

`docs/testing/traceability.md` 记录来源文件、requirement id、scenario id、用例 id／文件、层次、数据条件、预期、执行证据；反向从用例查需求。自动比较全部规格场景与用例索引，失败场景数不是覆盖率替代品。手工检查有独立记录；UI07、SG05 的未来条件场景登记“未启用”和入口／依赖清单证据，当前适用性核验本身必须执行。

安全矩阵展开每个方法、嵌套资源和批量引用，至少包含学生 A、学生 B、不同年级学生 C、管理员 A/B、禁用用户与匿名主体。管理员共享题库不要求同级隔离，但个人资料、附件与禁止字段仍需检查。

### 3. 隔离和关键边界数据

每次运行生成 run_id 并创建专属 PostgreSQL schema；每例前后清理，迁移用独立实例，清理失败使运行失败。连接保护检查测试标记与明确 allowlist，禁止从生产 URL 派生库名。保留失败证据时先脱敏，运行后清理数据。

必测边界：start_at 前／相等／后，end_at 前／相等／后；评分 -0.01／0／满分／满分+0.01；pageSize 0／1／100／101；501 收件人；头像和题图字节上限两侧；相同排序键跨页；同任务并发开始；同键同载荷和异载荷；旧版本更新；事务回滚；Outbox 租约过期与重试；删除文件中断；旧会话撤销；未提交答案泄露。

测试时钟推进模拟截止，不调用真实系统日期等待。离线是“依赖和浏览器镜像准备好后不访问外部网络”，本地 PostgreSQL／应用仍需要本地网络；禁止将真实邮件、模型或远程附件当测试依赖。

### 4. 业务信号、断言与性能

判定顺序：先看 code 确认业务接受／拒绝，再看返回数据、数据库与副作用是否符合授权和不变量，最后独立核对 HTTP 映射。HTTP 200 + 非 OK 是业务拒绝，若契约规定 409 则仅 HTTP 映射有缺陷；即使非 OK，若已写他人数据仍是“被放行”。随机五条失败样例双人复核 VT07 四词定义。

| 正向用例类别 | 标记阈值（超过） | 失败阈值（超过） | 测量范围 |
| --- | --- | --- | --- |
| 普通接口 | 500 ms | 1000 ms | 客户端发起至完整响应解析 |
| bcrypt 登录／注册／改密 | 1000 ms | 2000 ms | 同上，包含密码散列 |
| 浏览器主路径 | 5000 ms | 10000 ms | 自动开始首个动作至最终结果可见，不含人为停顿 |

基准采用运维 OB03 同档环境，预热 30 次后记录每个正向用例原始耗时，计时使用单调时钟。负向不用上述阈值，但每个请求仍有最大 10 秒测试超时，故障返回须满足适配器超时契约。端到端单例阈值与容量测试 p95 是不同门禁，两者都需满足；不能用一次快速结果替代负载分布。

关键规则以受控临时变异证明测试能发现：反转时间比较、取消授权、移除数据库唯一约束、总分漏加一题。变异只在临时测试副本进行，捕获失败后恢复；不为低影响样式添加镜像式测试。

### 5. 运行与门禁设计

计划 `pwsh ./scripts/test.ps1` 完成环境自检、隔离数据准备、所有适用层次执行、汇总及清理；报告写 `artifacts/test/<run-id>/`，包括 JUnit、追溯缺口、性能 JSON 与必要截图。README 写明 Docker、PowerShell、运行器、测试库与测试前后端地址等环境键；缺必需变量非零退出。

`pwsh ./scripts/gate.ps1` 在测试外串联 OpenSpec 严格校验、格式、架构、接口一致性、场景覆盖、机密、许可证及漏洞检查。结果绑定提交号，失败立即或汇总后非零退出，不因后续成功覆盖失败码。初始跳过基线为零；当前条件不适用登记与未实现任务严格区分。

在线漏洞信息更新是独立供应链门禁，不能要求离线业务测试去访问漏洞服务，也不能因离线就宣称安全门禁通过。测试基础可先完成，完整运行等待被测应用具备；不得把“脚本写好”标成“所有验收通过”。

### 6. 评审与完成责任

QA01–QA06 适用于全部五个 change：每 PR 一个任务组、最多 20 手写文件；人工查业务与授权，Harness 查一致性与证据索引，格式工具查风格；具名审核者两个工作日响应，超时升级维护者。`docs/changes/<name>/change-log.md`、`verification.md`、`review.md` 为三类证据，必须含 commit 和实际执行结果。人员名单由项目维护者在首个实施 PR 指派，不影响本提案规格。

## Risks / Trade-offs

- [尚无生产前端] → 明确 E2E 就绪依赖，不降低成品完成条件。
- [计时抖动] → 固定环境、预热、原始数据与独立容量报告，超标调查后修复，不静默重试直到绿。
- [追溯矩阵形式化] → 对关键不变量执行变异，要求真实副作用断言。

## Migration Plan

先建立运行器、隔离与追溯校验，再随账号、题库、答卷、消息接入用例，最后接安全与运维演练。测试规则变更和阈值变更走规格修订；回退用版本恢复测试脚本但不移除仍有效的业务防护用例。每次缺陷先保留复现测试再修复实现。
