# Spec Delta

## Purpose

建立可独立重复执行的考试平台验证体系，使业务场景、安全边界、数据一致性和运行行为都有可追溯证据，并统一用例分层、故障判定、有效断言与性能标记口径。

## ADDED Requirements

### Requirement: VT01 测试层次与三类组织
测试 SHALL 分为业务规则单元、每条能力正常与失败路径接口、仅关键主路径端到端三层；每层按正常、失败、边界分类。失败用例数 SHALL 不少于适用规格失败场景数，边界值取等价类两端及越界值，界面局部状态用组件测试或设计走查而非扩大端到端范围。

#### Scenario: VT01-N 分层检查
- **WHEN** 核验任务一次性、时间窗口、自行批改、授权与主路径用例
- **THEN** 规则有单元测试，API 有正常失败边界测试，端到端仅保留注册考试闭环和管理发布消息主路径

### Requirement: VT02 场景双向追溯
每个适用规格场景 SHALL 至少关联一组用例或明确的人工检查记录，用例须回链 change、capability 和场景编号；每条资源读写同时关联 IA07 越权矩阵。条件性未来能力 SHALL 登记未启用及证据，不得把已适用未实现功能标为不适用。

#### Scenario: VT02-F 遗漏与伪覆盖
- **WHEN** 出现无用例场景、无来源用例、缺越权配对或 mock 代替真实集成验收
- **THEN** 覆盖检查失败并列明缺口，不得仅凭总覆盖率宣布完成

### Requirement: VT03 数据与顺序隔离
自动测试 SHALL 使用真实 PostgreSQL 独立实例或隔离 schema，连接保护拒绝生产目标；每例前后清理并创建专属数据，使用合成数据且不依赖顺序。并发唯一约束和迁移 SHALL 在真实 PostgreSQL 验证，不以 SQLite 或内存替代。

#### Scenario: VT03-N 随机与并行
- **WHEN** 将用例随机排序并重复并行运行
- **THEN** 结果一致，无数据串扰、残留或其他用例顺序依赖

### Requirement: VT04 外部依赖与时钟可注入
业务测试 SHALL 使用可注入时钟、存储和通知适配器替身，不调用真实外部服务、不依赖真实日期。测试环境依赖安装完成后 SHALL 可断开外网运行；本地 PostgreSQL 和浏览器为测试依赖，性能计时使用单调时钟。

#### Scenario: VT04-N 离线截止测试
- **WHEN** 断开外网并将测试时钟依次推进到截止前、截止点和截止后
- **THEN** 测试可运行并稳定验证边界，既不睡眠等待真实截止，也不调用外部通知或模型

### Requirement: VT05 一键执行和通过门槛
README SHALL 写明 `pwsh ./scripts/test.ps1`、依赖、环境键、退出码和报告位置；单次命令运行全部适用单元、接口、组件、端到端及正向耗时检查。失败 SHALL 非零退出，无“已知失败”豁免；跳过项必须登记原因、责任人和到期日，数量不得高于已有基线，初始基线为零。

#### Scenario: VT05-F 失败传播
- **WHEN** 任一用例失败、必要服务未启动或未登记的测试被跳过
- **THEN** 总命令非零退出，报告标明原因而非部分通过，CI 阻断

### Requirement: VT06 有效断言与变更回归
断言 SHALL 验证业务结果及无副作用等不变量，不得仅断言不抛异常或数量相等。每次变更须更新对应场景用例；修复缺陷须先添加可复现用例。关键规则 SHALL 通过受控破坏逻辑证明对应测试会失败，破坏不进入主代码。

#### Scenario: VT06-N 变异验证
- **WHEN** 临时移除任务唯一性校验、反转截止比较或绕过归属判断
- **THEN** 对应用例变红并指出错误结果；恢复正确实现后通过，归档修改及结果证据

### Requirement: VT07 成败信号与缺陷定义
本系统有独立业务码，业务成败 SHALL 以 code=OK 判成功；HTTP 契约另行验证，不得把 HTTP 200 且非 OK 误判为业务放行。“被当成成功”指应拒绝却返回 OK；“被放行”指越权返回受限数据或产生副作用；“被误拒”指合法请求被拒；“未处理故障”指堆栈、无限等待或“系统错误”等无可执行信息的响应。

#### Scenario: VT07-N HTTP 200 但业务拒绝
- **WHEN** 分类器收到 HTTP 200、code=BIZ_VERSION_CONFLICT 且无副作用
- **THEN** 判为业务已拒绝，不报告被放行；若接口契约要求 409，另报 HTTP 映射缺陷

#### Scenario: VT07-F 四词一致性
- **WHEN** 两位评审分别判定五条失败样例，包括非 OK 却写入数据及暴露堆栈
- **THEN** 使用相同四词定义得出一致结论，非 OK 掩盖不了已发生的越权副作用

### Requirement: VT08 正向响应耗时两档
每个正向接口和端到端用例 SHALL 记录从发起到可用结果的单调时钟耗时并应用设计矩阵：普通 API 500 ms 标记／1000 ms 失败，密码散列类 1000／2000 ms，浏览器主路径 5000／10000 ms；等于阈值不超限，超过才触发。负向用例 SHALL 不纳入该性能判定，仍需故障超时限制。

#### Scenario: VT08-N 两档结果
- **WHEN** 普通正向 API 耗时分别为 500、750、1001 ms
- **THEN** 依次为正常、标记但不失败、性能不通过；报告包含环境和原始耗时

#### Scenario: VT08-F 不混淆负向耗时
- **WHEN** 负向用例按契约被拒绝但耗时超过普通正向标记阈值
- **THEN** 不因正向性能阈值误判，仍检查是否超出该故障路径的最大超时
