# Spec Delta

## Purpose

为独立前端提供在线考试平台的全部业务资源行为，确保账号、题库、试卷、任务、答卷、错题、消息和统计具有确定的输入输出与状态规则，并在重复请求和并发操作下维持正确结果。

## ADDED Requirements

### Requirement: API01 前后端分离和功能契约
系统 SHALL 通过版本化 HTTP JSON API 提供 README 全部业务能力，前后端独立构建部署，前端不得直接访问 PostgreSQL 或依赖后端页面模板。API 文档 SHALL 逐项关联 PX01–PX08 与页面清单并声明授权、幂等和错误。

#### Scenario: API01-N 独立调用
- **WHEN** 测试客户端不启动前端而调用业务 API
- **THEN** 能完成完整的题库到答卷消息流程，返回结构化数据；前端通过相同契约集成

### Requirement: API02 账号和个人空间
服务 SHALL 提供学生注册、两角色登录的安全接入点、个人资料与头像更新、学生近期动态和管理员创建时间线。管理员 SHALL 可查询、新增、修改、删除、禁用两类账号；公开注册只能创建学生，禁用或删除立即撤销会话，最后一个启用管理员受到保护。

#### Scenario: API02-N 注册和管理
- **WHEN** 使用合法年级、用户名、密码注册，再由管理员修改和禁用该学生
- **THEN** 建立唯一学生账号，变更可查询且有审计，禁用后旧会话下一次请求被拒绝

#### Scenario: API02-F 非法账号操作
- **WHEN** 请求重复用户名、伪造管理员角色、修改他人资料或并发移除最后的有效管理员
- **THEN** 返回对应业务拒绝码，既有资料不变且至少保留一个有效管理员

### Requirement: API03 学科题库和试卷管理
管理员 SHALL 可查询、创建、修改、删除学科、五题型题目以及固定／时段／任务试卷。题干 SHALL 保存受约束的文本、图片引用、表格和公式，题目须有参考答案、分值和学科。已引用版本 SHALL 不被原地破坏，删除须归档或因引用拒绝。

#### Scenario: API03-N 创编和版本
- **WHEN** 管理员更新已被答卷引用的题目或试卷
- **THEN** 后续新答卷使用新版本，既有答卷仍显示原题干、分值和参考答案快照

#### Scenario: API03-F 无效内容
- **WHEN** 请求无效题型、负分值、不存在学科或携带未经授权的图片引用
- **THEN** 拒绝整次写入，错误指出无效字段且不留下半份试卷

### Requirement: API04 年级任务与开始作答
管理员 SHALL 可查询、创建、发布、修改、删除年级任务，发布时固定目标年级、试卷版本与目标学生集合；发布后的内容不可改写。服务 SHALL 对每个任务和学生至多创建一份答卷，重新进入返回该答卷。固定练习和有效时段内的时段练习允许新建独立答卷。

#### Scenario: API04-N 并发开始
- **WHEN** 同一目标学生同时向同一任务发送两次开始请求
- **THEN** PostgreSQL 中只有一份任务答卷，两次请求返回同一答卷或明确的已存在结果

#### Scenario: API04-F 可用范围
- **WHEN** 非目标学生开始任务，或时段试卷在 start_at 之前或 end_at 及之后开始
- **THEN** 返回不可访问或不可开始业务码且不创建答卷；时段区间为 start_at 小于等于当前时间且当前时间小于 end_at

### Requirement: API05 作答和截止处理
答卷 SHALL 接受按题型校验的文本答案，作答中可保存草稿；仅服务端决定提交状态。截止时间前已保存的草稿 SHALL 在截止后冻结为待批改答卷，过期请求不得覆盖草稿；服务端以可注入时钟判断。提交 SHALL 原子保存最终答案和提交记录。

#### Scenario: API05-N 正常提交及重试
- **WHEN** 学生提交有效答案后网络断开，并使用同一幂等键重试
- **THEN** 返回原提交结果，只产生一次提交记录且答案完整

#### Scenario: API05-F 截止边界
- **WHEN** 当前时间到达 end_at 后收到新的答案或提交请求
- **THEN** 将截止前已保存的草稿冻结为待批改，拒绝新答案，客户端可查看被冻结的结果和明确的截止提示

### Requirement: API06 自行批改和错题一致性
提交后 SHALL 对本人开放参考答案与自行批改；五题型均允许在每题 0 到满分之间确认得分，分数采用精确小数，系统计算总分。任务本期同样自行批改且不宣称受监考成绩。确认后 SHALL 原子生成最终成绩及得分低于满分的错题，完成态禁止普通修改。

#### Scenario: API06-N 评分与错题
- **WHEN** 学生确认包含部分得分题目的批改
- **THEN** 总分等于逐题分数之和，未满分题出现在个人错题本，同一学生同一原始题目只保留一条汇总并关联最近错误答卷

#### Scenario: API06-F 非法或并发评分
- **WHEN** 学生提交超出满分的评分、批改他人答卷，或两个会话同时确认同一版本
- **THEN** 非法评分和越权被拒绝，合法并发只有一次生效，后者得到已处理提示且不覆盖成绩

### Requirement: API07 历史记录与内容归属
服务 SHALL 分页返回本人考试记录、试卷快照、错题与近期动态，并在每次详情请求校验归属；未提交答卷 SHALL 不返回标准答案。已归档原试卷 SHALL 不使历史记录失效。

#### Scenario: API07-N 归档后的历史
- **WHEN** 管理员归档原试卷后学生查看历史答卷
- **THEN** 仍能看到当时试卷信息、个人答案和已开放的批改结果

#### Scenario: API07-F 水平越权与答案泄露
- **WHEN** 学生替换答卷、错题、动态标识或请求未提交答卷的参考答案
- **THEN** 他人资源返回与不存在一致的响应，本人未提交记录不包含参考答案字段

### Requirement: API08 消息投递和已读统计
管理员 SHALL 向多个明确用户发送同一消息，事务内建立收件人记录并写入 Outbox，站内消息以提交成功为可见。用户 SHALL 只能读取自己的收件记录；重复阅读不得增加人数。失败异步投递 SHALL 重试且不得重复产生站内消息。

#### Scenario: API08-N 多用户消息
- **WHEN** 管理员发送包含重复收件人标识的消息，一名用户多次标记已读
- **THEN** 每人一条收件记录，发送列表的已读人数只增加一人，发送内容不可普通编辑

#### Scenario: API08-F 无效收件人与越权
- **WHEN** 消息包含不存在的收件人，或学生发送管理消息、读取他人收件记录
- **THEN** 整次发送或访问被拒绝，无部分发送、无他人已读状态泄露

### Requirement: API09 管理统计和用户日志
管理员 SHALL 查询试卷总数、题目总数、最近 30 日每日活跃用户及最近 12 月新增题目数，统计以 UTC 存储时间和 Asia/Hong_Kong 日历分组，显式标注口径；活跃定义为当日有成功认证业务请求的去重用户。用户日志 SHALL 记录业务变更且仅提供脱敏查询。

#### Scenario: API09-N 确定性统计
- **WHEN** 同一用户一天进行多次业务操作且存在归档题目
- **THEN** 活跃人数只计一人，总数仅计未删除未归档记录，月新增按创建事件统计且不因后来归档改写历史

#### Scenario: API09-F 功能越权
- **WHEN** 学生调用主页统计或全体用户日志接口
- **THEN** 返回授权拒绝，不返回统计或日志内容
