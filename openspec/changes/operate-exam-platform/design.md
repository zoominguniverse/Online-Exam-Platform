# Design

## Context

见 proposal.md。本提案以 reference 的部署运维标准确定部署协议和验收目标，不绑定特定云平台。前后端独立、PostgreSQL、私有文件和 Outbox 是其他 change 的架构输入，恢复必须覆盖它们之间的一致性。

## Goals / Non-Goals

**Goals:** 用固定镜像交付三环境；蓝绿切流可回退；观测请求和异步事件；证明故障时数据可恢复且删除记录不会复活。

**Non-Goals:** 不立即购买云资源、部署生产、不引入 Kubernetes 或多区域主动主动架构，不将生产前端缺失时的后端部署称为全站上线。

## Decisions

### 1. 独立容器和同站网关

最小运行拓扑：HTTPS 网关 → 前端静态容器与 API 容器；API／Outbox 工作进程 → PostgreSQL 与私有文件存储。工作进程复用后端镜像以不同启动命令运行，数据与文件使用持久存储，数据库不暴露公网。开发与测试可用 Compose，生产使用同样健康与切流协议的蓝绿脚本，保持基础设施厂商中立。

前端、后端各多阶段构建，基础镜像按摘要锁定、依赖锁入库、最终层只含产物和必需运行时、非 root 运行；统一构建时间源、稳定文件顺序。记录运行产物摘要，镜像元数据若包含构建证明需分离，以免非运行元数据误导可复现检查。发布以提交标签及镜像摘要绑定，不用浮动标签。

同源 `/api` 转发到独立服务，让 Strict Cookie 与安全来源校验生效。前端运行时读取不含秘密的公开配置，避免把 API 地址烘进每环境不同镜像；密钥由部署环境注入服务环境变量，普通环境变体另存声明。选择蓝绿优于逐实例滚动的原因是首期规模小且切回路径清晰，代价是短期双份应用资源。

### 2. 配置与健康协议

环境分开发／测试／生产，数据库、存储、会话密钥完全隔离；共用同一镜像摘要。启动检查必需键，缺失拒绝；Secret 值只在注入通道，README 和配置样例仅写键名与说明。

`/health/live` 无外部依赖检查，`/health/ready` 检查迁移版本、PostgreSQL 及必要文件存储连接。健康接口仅运维网络访问且返回最小信息，授权注册表显式登记内部权限。停止：先撤 readiness，网关停止新流量，工作进程停止领取事件，等待最多 30 秒在途请求／短事务完成，释放资源退出；平台终止宽限期至少 40 秒。超过宽限中断的事务自动回滚，重试依赖业务幂等和事件租约。

### 3. 发布和数据库兼容

计划命令为 `pwsh ./scripts/release.ps1 -Version <tag>` 和 `pwsh ./scripts/rollback.ps1 -Version <previous-tag>`，实现时 README 明确权限、配置、输出和错误码。

发布依次：验证当前提交门禁 → 记录并备份 → 兼容扩展迁移 → 启动绿色 API／worker／前端 → 就绪与业务冒烟 → 切流 → 观察 15 分钟 → 归档。观察期普通接口 p95、错误率或关键考试路径失败触发回滚决策，目标 10 分钟切回上版。Outbox 消费者必须兼容前一版本事件，双 worker 并存由租约去重。

保留前一版本镜像、运行配置快照和数据库兼容性至少 7 日。结构顺序固定为加字段→双写→切读→停止旧写→窗口后删旧字段，删除独立发布；旧代码在新 schema 上的测试是切流前条件。自动回滚只换应用与兼容配置，不自动 down 破坏性迁移；收缩后恢复需要备份与明确数据影响。

### 4. 可观测性和责任表

JSON 日志带 requestId，异步带原始 requestId/eventId，查询与错误不记录答案、令牌、Cookie。指标低基数标签只用模块、路由模板、结果类型和环境，用户 id 不作为时序标签。

| 告警 | 阈值／持续 | 责任角色 | 首要处置 |
| --- | --- | --- | --- |
| 依赖断连 | 连续 1 分钟 | 运维值班 | 检查连接与凭据，撤流并恢复依赖 |
| 可用性错误率 | 5 分钟超过 1%，至少 100 次请求 | 运维，升级后端 | 关联请求日志，查新版本并决定回滚 |
| 普通 API 延迟 | p95 >500 ms 持续 5 分钟 | 后端，运维协作 | 定位 SQL／外部适配器，检查池与负载 |
| Outbox 堆积 | 最老事件 >5 分钟 | 后端 | 检查 worker、失败队列和消费者，按事件重试 |
| WAL 归档延迟 | >5 分钟 | 运维 | 恢复归档链，评估 RPO 风险 |
| 备份失败／校验失败 | 发生即告警 | 运维 | 重试备份、隔离损坏件并验证恢复点 |
| 会话重放／泄露线索 | 确认重放或机密扫描命中 | 安全 | 撤销会话／密钥，归档事件 |

投产前值班表映射到具名人员与通知渠道，演练触发通知并记录到达；此提案不主动发送任何外部消息。业务错误与服务故障分开统计，401／403／409 等预期拒绝不全部计作服务故障。

### 5. 容量、限流和配额

OB03 为首期预算，不是假称现有系统测量值。使用合成数据：1000 学生、10000 题目、1000 试卷、100000 历史答卷；100 并发在线、20 RPS，含 10 RPS 提交，测量预热后的 15 分钟。列表／普通写 p95≤500 ms、提交≤1000 ms、认证≤1500 ms；慢操作阈值 500 ms，异常必须定位到具体调用。

限流计数初期使用 PostgreSQL 独立短事务的原子窗口计数，不混入业务事务，避免额外 Redis 依赖与多副本计数漂移；所有实例共用主体和时间窗，失败关闭而不绕过。滚动窗口限制每分钟总量，令牌桶限制突发 10 次；登录键包含账号摘要和可信代理校验后的 IP。最大列表 100、收件人 500、Outbox 批量 100；超限返回 429 及 Retry-After，不排队。若数据库限流成为瓶颈，另行规格评审替换计数实现但不改变外部配额契约。

本期没有模型或检索出站。私有存储并发、超时、重试按 OB04；Outbox 外层重试统一计算总预算，避免嵌套重试放大流量。可用性探针不消耗用户配额但只允许运维来源。

### 6. 备份、恢复和删除

每日 PostgreSQL 全量和持续 WAL、文件最长 15 分钟增量及版本保护，保留 30 日。加密密钥与备份分开管理，在独立故障域存储，恢复角色与普通应用角色隔离。RPO≤15 分钟、RTO≤60 分钟覆盖整体服务，不只数据库启动。

恢复步骤：故障确认计时→隔离恢复环境→验证全量与 WAL 链→恢复目标数据库点→匹配文件版本／清单→补偿 Outbox→重放独立保存的删除清单→撤销所有恢复旧会话→验证外键、成绩、错题、附件和权限→切流。账号删除在线数据 24 小时内清理，备份最长 30 日到期，删除标记独立保存至少 31 日。缓存重建，向量库标为不存在。

每月及关键变更后演练，记录真实数据损失窗口与用时，故障中途注入文件缺失和删除任务失败。恢复不一致不能以进程健康替代业务通过。发布记录归档 docs/releases，手册和演练归档 docs/operations，并链接所属 change 三类证据。

## Risks / Trade-offs

- [蓝绿双份资源] → 小规模采用明确容量预算，保留回滚能力优先。
- [PostgreSQL 限流增加写入] → 短事务、索引和过期清理，容量测试实测，超标不直接放宽限流。
- [备份数据库与文件时间不一致] → 版本化清单、恢复点对齐、完整性验证和补偿后再开放流量。
- [缺实际云平台和具名值班人] → 实施首次配置时填写环境清单与值班表；协议、目标和任务已确定，无需改变规格。

## Migration Plan

先在开发／测试实现镜像与配置，再接健康、日志、限流和备份，执行完整蓝绿与恢复演练后才能申请生产发布。首次发布也必须有可回退基线或停机恢复方案记录。回滚演练成功并不替代恢复演练，两者分别记录目标和实测值。全部完成条件遵循 QA01–QA06。
