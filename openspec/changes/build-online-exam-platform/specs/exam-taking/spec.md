# Spec Delta

## Purpose

规定学生从开始考试到交卷的可观察行为，以服务端时间和持久化答案作为共同依据，让刷新、断网、切后台和Web 多会话并发情况下的作答结果保持一致。

## ADDED Requirements

### Requirement: ET01 开始与恢复
开始答卷 SHALL 返回题目快照、服务端时间、截止时间、已保存答案及版本。截止时间为开始时间加卷时长，时段卷取该值与开放结束时间的较早值。刷新或按答卷标识在另一 Web 会话进入 SHALL 恢复相同答卷。

#### Scenario: ET01-N 刷新与多会话恢复
- **WHEN** 学生保存答案后刷新 Web 或在另一 Web 会话打开该答卷
- **THEN** 已保存答案、截止时间和题序一致，计时继续且不重新分配时长

#### Scenario: ET01-B 客户端时间变化
- **WHEN** 客户端修改时钟或长时间切后台后回到前台
- **THEN** 重新同步服务端时间，服务端仍按原截止时间决定可写性

### Requirement: ET02 保存与断网反馈
作答中 SHALL 自动保存文本或选项答案，提供已保存、保存中、待重试状态。离线暂存须按用户和答卷隔离，联网后仅在截止前以匹配版本重试。其他会话更新时 SHALL 返回冲突并提示加载服务端版本。

#### Scenario: ET02-N 保存确认
- **WHEN** 学生修改答案并收到保存成功响应
- **THEN** 再次读取返回该答案和递增版本，页面显示已保存

#### Scenario: ET02-F 离线未保存
- **WHEN** 答案修改后断网且尚未收到成功确认
- **THEN** 页面显示待同步并保留本地草稿，退出账号清除该账号本地草稿

#### Scenario: ET02-B 旧版本写入
- **WHEN** 两个独立 Web 会话基于相同版本保存不同答案
- **THEN** 仅一个成功，另一个得到冲突提示，其载荷不能静默覆盖新版本

### Requirement: ET03 交卷和截止冻结
手动交卷 SHALL 在一个原子操作内校验版本、保存完整最终答案并冻结答卷。截止时 SHALL 自动冻结截止前已确认保存的答案，未答计零；截止后载荷不得补写。重复提交返回既有结果，冻结及计分的效果只发生一次。

#### Scenario: ET03-N 手动交卷
- **WHEN** 截止前提交有效最终答案
- **THEN** 答卷冻结并进入待批改或完成状态，后续编辑失败

#### Scenario: ET03-B 截止和重试并发
- **WHEN** 自动截止处理与手动提交竞争，或提交成功响应丢失后重试
- **THEN** 返回唯一冻结结果，所有答案和成绩来源于同一次成功冻结，重复请求不产生额外答卷

#### Scenario: ET03-F 断网跨过截止
- **WHEN** 学生离线期间到时并于截止后重传未确认的答案
- **THEN** 服务端返回按已保存答案冻结的结果，页面明确说明未同步答案未计入

#### Scenario: ET03-F2 非法题目载荷
- **WHEN** 提交包含卷外题目、重复题目、无效选项或超过限制的文本
- **THEN** 整体拒绝且不发生部分保存或交卷，截止处理仍按原时间运行
