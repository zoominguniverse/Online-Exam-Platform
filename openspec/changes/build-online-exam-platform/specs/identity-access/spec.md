# Spec Delta

## Purpose

规定学生、管理员和微信用户进入考试平台的身份规则，以及账号管理和资源归属边界，确保三个客户端对同一账号状态和权限作出一致、可验证的处理。

## ADDED Requirements

### Requirement: IA01 注册登录与会话撤销
系统 SHALL 允许学生以有效年级、用户名和密码注册，允许启用账号登录和退出。用户名规范化后唯一，角色由服务端决定，密码单向存储。禁用、删除及改密 SHALL 撤销既有会话。

#### Scenario: IA01-N 注册登录退出
- **WHEN** 学生使用有效信息注册、登录并退出
- **THEN** 返回学生身份，退出后的原凭据无法读取个人数据

#### Scenario: IA01-F 非法注册和凭据
- **WHEN** 用户名重复、年级不存在、密码不合要求或登录凭据错误
- **THEN** 返回明确业务错误且不创建账号或会话，注册输入中的管理员角色被拒绝

#### Scenario: IA01-B 账号即时禁用
- **WHEN** 管理员禁用一个已在 Web 和小程序登录的学生
- **THEN** 两端下一次受保护请求均失败，恢复启用后须重新认证

### Requirement: IA02 管理账号与资源授权
管理员 SHALL 查询、新增、编辑、禁用和删除学生及管理员。最后一个启用管理员 SHALL 受到并发保护。学生仅能访问本人的答卷、错题、资料、消息和动态，管理接口仅向管理员开放。

#### Scenario: IA02-N 账号管理
- **WHEN** 管理员创建、筛选、编辑并删除一个学生账号
- **THEN** 列表和状态反映操作结果，历史答卷保留稳定归属并显示已删除账号

#### Scenario: IA02-F 跨用户访问
- **WHEN** 学生篡改答卷、消息或资料标识，或调用管理接口
- **THEN** 他人资源返回不存在，管理接口返回无权限，响应不暴露资源内容

#### Scenario: IA02-B 最后管理员并发删除
- **WHEN** 两个管理员同时尝试禁用或删除对方，操作将导致无启用管理员
- **THEN** 至少一个操作被拒绝，事务结束后仍有启用管理员

### Requirement: IA03 微信绑定与解绑
小程序 SHALL 使用微信登录 code 与平台凭据建立学生账号绑定。一个微信身份与一个平台学生账号各自最多绑定对方一个身份。微信 code 仅由服务端交换身份，解绑及小程序退出 SHALL 撤销该绑定的全部小程序会话。

#### Scenario: IA03-N 绑定和自动登录
- **WHEN** 学生用有效平台凭据和微信 code 绑定后再次进入小程序
- **THEN** 校验绑定后进入同一账号，Web 与小程序可见相同的个人业务数据

#### Scenario: IA03-F 身份冲突与微信故障
- **WHEN** 身份已被其他账号绑定、code 无效、微信服务失败或账号被禁用
- **THEN** 返回可重试或需解绑的明确错误，原绑定关系保持完整

#### Scenario: IA03-B 解绑后重试旧令牌
- **WHEN** 学生解绑后以旧小程序令牌访问或重放绑定 code
- **THEN** 访问失败，再次绑定需要新的微信 code 和平台认证
