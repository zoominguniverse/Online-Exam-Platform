# Spec Delta

## Purpose

规定管理端、学生 Web 端与原生微信小程序的页面覆盖和交互行为，使用户可以通过真实界面完成全部业务流程，并在加载、空数据、故障和权限变化时获得明确反馈。

## ADDED Requirements

### Requirement: CX01 三端业务入口
三端 SHALL 提供 design 功能对照表列出的规范页面，使用共用业务接口和规则。管理端覆盖账号、学科、题库、试卷、任务、答卷、消息、日志、统计和资料；学生 Web 覆盖注册登录、任务试卷、作答批改、记录错题、资料动态和消息；小程序覆盖绑定解绑、注册、任务试卷、作答批改、记录、资料动态和消息。

#### Scenario: CX01-N 全流程可达
- **WHEN** 管理员发布五题型任务，学生分别通过 Web 和小程序完成答题与批改
- **THEN** 所有步骤均有可访问页面，管理员可查成绩，学生可查记录和消息

#### Scenario: CX01-F 路由与权限
- **WHEN** 访问未知路由、未登录页面或错误角色页面
- **THEN** 分别展示返回入口的 404、登录引导、无权限提示，不显示缓存的受保护数据

### Requirement: CX02 页面与表单状态
所有数据视图 SHALL 显示加载、正常、空、错误状态及可执行下一步。表单有标签、字段校验、提交中状态，失败保留可安全保留的输入。Web 主路径键盘可达，在 375、768、1440 像素宽度下可操作，正文对比度至少 4.5 比 1。

#### Scenario: CX02-N 空状态与恢复
- **WHEN** 首次注册用户打开空记录列表，或请求失败后重试成功
- **THEN** 空状态说明如何开始考试，错误可重试且成功后恢复列表

#### Scenario: CX02-F 重复操作
- **WHEN** 保存处理中连续点击按钮
- **THEN** 页面抑制重复动作，超时后允许用同一操作标识重试并显示服务端最终结果

#### Scenario: CX02-B 可达性与窄屏
- **WHEN** 使用键盘完成 Web 登录和答卷，或在窄屏查看长表格
- **THEN** 焦点可见、标签可读，表格可横向滚动，提交按钮可到达

### Requirement: CX03 考试交互一致性
学生客户端 SHALL 显示题号导航、已答与未答标识、标记复查、剩余时间、保存状态和提交确认。手动交卷前显示未答数量，到时直接进入服务端结果流程。切换账号 SHALL 清除前一账号的本地缓存。

#### Scenario: CX03-N 导航与确认
- **WHEN** 学生标记题目、切换题号并手动交卷
- **THEN** 已填答案保持，导航准确显示状态，确认框显示实际未答数

#### Scenario: CX03-B 到时与账号切换
- **WHEN** 倒计时归零或用户退出后换账号
- **THEN** 到时停止编辑并同步冻结结果，新账号界面不显示前一账号的答案或消息
