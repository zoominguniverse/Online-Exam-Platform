# Proposal

## Why

README 已列明学生端和管理端功能，但尚无页面、交互与流程契约。需要依据 `reference/规范验收标准.md` 把每项能力转为可评审、可实现、可验收的产品设计，避免后端和测试各自解释规则。

## What Changes

- 建立 README 功能到角色、触发操作、页面、场景的完整映射，覆盖学生端 12 项、管理端 17 项能力。
- 设计路由层级、四类视图状态、术语表、表单规则、视觉令牌、可达性与响应式基线。
- 定义固定／时段／任务试卷、答卷、自行批改、错题、消息、账号和内容管理的状态与并发冲突交互。
- 交付页面规范和可走查原型，明确导入导出与 AI 的适用条件；README 未要求它们，本期不新增这些业务入口。
- 建立设计变更与 README、页面清单、验收场景的同步机制。

## Capabilities

### New Capabilities

- `exam-experience`: 学生学习考试与管理员管理流程的页面、入口和可观察行为。
- `interaction-standards`: 视图状态、文案、表单、视觉、可达性、响应式与产品追溯契约。

### Modified Capabilities

无；当前没有主规格。

## Impact

后续交付位置为 `docs/product/`、原型目录及 README「用户与场景」。本 change 的实施范围是产品设计及原型，不等同于生产前端实现；前端实现需要另行安排，但必须遵循这些契约，测试和部署不得在前端缺失时宣称整个平台完成。

依赖：无。为 `build-exam-backend` 提供业务语义，为 `secure-exam-platform` 提供角色和资源边界，为测试和部署提供验收输入。五个提案共用的覆盖索引与实施次序见 [整体规划](../planning-overview.md)。
