# Design

## Context

README 列出了学生端与管理端的必要功能，reference 定义了页面、交互和流程验收标准。动机见 proposal.md；行为见 exam-experience 与 interaction-standards。此设计处理两角色、三类试卷和跨页面状态，需形成统一产品语义。

## Goals / Non-Goals

**Goals:** 交付可以逐页走查的产品规范与交互原型，形成“功能—角色—触发—路由—场景”链路；固定信息架构、状态和验收口径。

**Non-Goals:** 此 change 不承诺生产前端实现，不新增监考、支付、教师角色、AI 阅卷或业务导入导出。原型不能代替真实前后端端到端验收。未来生产前端实现应承接本设计，作为另行安排的工作。

## Decisions

### 1. 以两个应用区域组织唯一入口

学生区域 `/student`、管理区域 `/admin`，共享组件和术语，角色隔离导航。采用一功能一个规范路由，允许按钮链接到相同路由，不复制平行功能页。相比所有功能放在同一仪表盘，两区域更清晰地表达权限边界。

| README 功能 | 角色／触发 | 规范路由与入口层级 | 对应要求 |
| --- | --- | --- | --- |
| 学生登录 | 访客输入凭据 | `/student/login`，公开入口 | PX02、IA03 |

### 2. 将 README 留白明确为本次提案基线

- 时段是左闭右开区间 `[start_at,end_at)`，展示 Asia/Hong_Kong 时间并注明时区；服务端以 UTC 判定。固定试卷无额外时段限制。
- 任务由管理员创建并发布给一个年级，发布时冻结目标学生集合与试卷版本，之后调年级不撤销或新增该任务资格；一次是“一个任务一份答卷”，断线恢复不占第二次机会。
- 固定与时段练习按 README 自行批改；任务沿用自行批改，不额外假定教师阅卷。参考答案提交后才显示，分数用于学习记录，不声称具备监考可信性。
- 时段到期冻结最后已保存草稿并进入待批改；前端显示保存状态，提交响应丢失用原幂等键查询或重试。
- 题型答案采用选项文本／文本数组／文本对象等 JSON 表示，均为文本，不接收答题文件；每题评分范围为 0 至满分，最多两位小数，未满分记为错题。
- 已使用的内容通过版本快照保护历史。草稿可编辑，已发布内容变更产生新版本，已发送消息和已完成答卷无普通修改入口。

这些是拟议产品决策，不是 README 原文事实；若评审修改，应同步后端、安全和测试相关规格，不允许各端自行解释。

### 3. 状态、动作与并发一致呈现

| 对象 | 状态流转 | 允许动作／角色 | 终态与冲突 |
| --- | --- | --- | --- |
| 答卷 | 作答中 → 待自行批改 → 已完成 | 本人保存、提交、确认批改；服务端到期冻结 | 已完成只读，旧版本提示已被处理 |
| 题目／试卷／任务 | 草稿 → 已发布 → 已归档 | 管理员编辑草稿、发布、归档；内容新版本继承来源 | 已归档只读，历史快照保留；任务发布后不得改目标或卷面 |
| 消息 | 草稿 → 已发送 | 管理员编辑草稿、发送 | 已发送不可改，重试返回原发送结果 |
| 收件记录 | 未读 → 已读 | 收件人阅读 | 重复阅读幂等 |
| 账号 | 启用 ↔ 禁用；启用／禁用 → 已删除 | 管理员启用、禁用、删除 | 已删除不可恢复；最后有效管理员禁止停用或删除 |

前端传业务动作和预期版本，不提交目标状态；读到新状态后更新操作区。选择服务端仲裁而非只靠禁用按钮，是为防止多会话覆盖和直接 API 绕过。

### 4. 共享交互和视觉基线

产出 `docs/product/pages.md`、`glossary.md`、`forms.md`、`tokens.md`、`flows.md` 与原型索引。每页记录 UI01 四态和各态文案。间距令牌为 4／8／12／16／24／32 px，字号为 12／14／16／20／24／32 px；语义色定义成功、警告、错误、信息及其前景／背景配对，必须用实际对比度测量确认，不仅凭色值命名。

表单统一失焦单字段校验和提交全表校验，必填标识关联可访问描述；错误处聚焦，服务器拒绝映射为字段或全局错误。组件清单遵从 UI04，避免逐页重复设计。同一主按钮呈现空闲／处理中／成功／失败恢复状态。

| 视口 | 导航 | 列表 | 答题与编辑 |
| --- | --- | --- | --- |
| 320–767 px | 折叠菜单 | 卡片或局部可滚动表格 | 单列，答题导航折叠，操作栏不遮挡输入 |
| 768–1199 px | 可收起侧栏 | 精简列与可见筛选 | 主内容与可收起题号面板 |
| ≥1200 px | 固定侧栏 | 完整表格 | 主内容与侧边题号面板 |

视图在 200% 缩放下仍可操作；以键盘完成两条主路径并检查焦点、标签和对比度。导入导出按 UI07 记录条件，不创建本期入口。

## Risks / Trade-offs

- [生产前端不在本 change 实施范围] → 原型只做设计验收，真实端到端与前端容器等待前端工程交付，不隐瞒依赖。
- [自行批改不保证考试成绩真实性] → 界面明确学习／自行批改语义，受控阅卷须另提需求。
- [大量页面易遗漏状态] → 以 29 项映射和逐页四态检查表做 peer review，按 QA02 分组交付。

## Migration Plan

先提交角色与页面清单，再交付原型和组件令牌，同步 README 用户场景；后续生产前端按产品契约集成服务端流程。评审修改通过版本化文档回退并同步 API 与测试映射。最终按 QA01–QA06 归档设计走查和评审证据，不把原型截图标为生产功能已实现。
