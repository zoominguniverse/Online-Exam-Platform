# Proposal

## Why

答卷、错题、个人资料、附件与管理员操作存在不同访问边界。需要把 reference 的安全标准变成逐资源授权和可验证的安全行为，从首次提供接口就防止未授权访问和敏感信息泄露。

## What Changes

- 实现默认拒绝、显式授权登记与逐资源归属检查，所有资源场景配套水平和功能级越权场景。
- 建立密码单向存储、内存访问令牌、严格 Cookie 刷新轮换、立即撤销与禁用生效机制。
- 将题干图片和头像读取绑定业务对象，拒绝通用文件读取与公开附件目录。
- 统一输入验证、上下文转义、参数化查询、富文本净化、敏感字段和日志脱敏。
- 建立环境密钥、历史泄露轮换、出站限制、依赖许可证与漏洞阻断机制。
- 对外部内容和未来 AI 入口明确不可信边界，记录当前无模型调用的适用性结论。

## Capabilities

### New Capabilities

- `identity-access`: 认证、会话、角色与逐资源授权。
- `content-security`: 附件、输入输出、敏感数据与出站请求安全。
- `security-governance`: 密钥、依赖许可证、漏洞与外部内容治理。

### Modified Capabilities

无；当前没有主规格。

## Impact

影响前后端会话集成、后端中间件和服务、私有文件存储、依赖与 CI 门禁。依赖产品角色及后端资源契约；可先冻结安全契约再随接口接入，不能推迟到上线之后补做。测试 change 负责独立安全回归，运维 change 负责生产 TLS、环境注入和告警。参考 [整体规划](../planning-overview.md)。
