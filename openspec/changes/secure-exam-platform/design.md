# Design

## Context

动机见 proposal.md。现有仓库没有认证或附件实现，因此安全能力需随首次接口开发接入。角色只有学生和管理员，题库和管理功能是授权管理员共享域，学生学习记录为个人域。前后端分离不意味着跨站点：采用同站 HTTPS 网关，满足 Strict Cookie。

## Goals / Non-Goals

**Goals:** 明确每条入口与资源的权限；立即撤销会话；私有附件和富文本安全；以扫描和测试证明密钥、依赖和外部内容边界。

**Non-Goals:** 不新增 SSO、教师角色、模型工具、生产监考或第三方认证平台；不声称自行批改成绩不可伪造。

## Decisions

### 1. 双层授权加逐资源检查

接口路由注册表默认拒绝，业务用例取记录再检查归属；列表以授权范围作为查询前置条件，详情与关联对象仍单独验证。优于只在网关验角色的方案：角色正确不代表该答卷属于调用者。

| 资源 | 学生范围 | 管理员范围 | 必备失败测试 |
| --- | --- | --- | --- |
| 个人资料、头像、动态、会话 | 本人；角色／状态只读 | 账号管理的明示字段，不能取密码或会话令牌 | A 访问 B；学生管理账号；管理员滥取禁止字段 |
| 学科、题目、试卷、任务 | 已公开可用且有资格的内容，答案延迟开放 | 共享管理 CRUD／发布；受引用和终态约束 | 学生写入；无任务资格；引用他人私有上传 |
| 答卷、批改、错题 | 本人 | README 未要求代阅卷或全员答卷查看，默认不授予此能力 | A 读写 B；管理员调用未授予的批改能力 |
| 消息、收件记录 | 仅本人收件记录与已读操作 | 共享已发送管理列表和已读人数，发送内容不可改 | A 读取 B 收件记录；学生发送管理消息 |
| 审计与统计 | 无 | 脱敏查询 | 学生访问；响应含敏感原文 |
| 附件 | 根据关联题目／答卷／头像范围 | 根据管理业务授权 | 匿名、跨用户、错配关联、通用 fileId 访问 |

所有方法和嵌套引用展开成 `docs/security/authorization-matrix.md`，每条正常用例都有水平与功能级越权配对；共享管理资源的同级管理员允许访问不是水平越权，必须在矩阵中写清适用性，不能为满足计数捏造拒绝。

### 2. 可撤销的会话族

选用短期访问令牌（基线 15 分钟）加刷新令牌（基线 7 日），服务端持有 sessions 与令牌摘要，访问令牌载 session_id 和 auth_version。每次请求查询服务端会话与用户版本；优于纯无状态 JWT 等待过期方案，能满足立即撤销。

前端访问令牌只在内存，刷新 Cookie 使用 `__Host-` 前缀、Path=/、无 Domain、HttpOnly、Secure、SameSite=Strict；端点另验 Origin 和 CSRF。浏览器刷新页面通过 Cookie 换取新访问令牌。刷新在短事务内消费旧摘要并产生新摘要，检测重放撤销族；客户端跨标签协调为单次刷新，避免正常并发触发重放撤销，安全默认仍是不放行。

密码采用 bcrypt 带随机盐并遵守 IA03 的长度边界。本人改密先校验当前密码，同事务增加 auth_version 并撤销全部会话。登录限流与运维共用主体计数。管理员初始账号通过受控离线初始化生成，不提供公网“首个管理员注册”竞态入口，初始凭据不得写入日志。

### 3. 内容与文件安全

图片存私有目录或私有对象存储，以后端代理流式返回为基线，避免签名 URL 在有效期内绕过即时撤销。图片元数据绑定业务对象，临时上传仅上传者可管理；数据库确认引用后开放业务读取。头像与题干画像用不同限额，验证实际文件内容、像素与解码结果，移除元数据并重新编码，使用服务端生成的对象键。

题干以受约束结构保存，渲染用允许标签／属性的净化规则，移除事件、脚本和外链自动加载，公式渲染禁用任意宏执行。响应设置内容类型与禁止 MIME 嗅探；浏览器内容安全策略禁止任意内联脚本。参数化 SQL 和排序字段映射由后端基础实现，安全用注入载荷独立验证。私有存储连接属于受控内部基础设施，不等于允许业务参数任意 SSRF。

### 4. 数据分类与机密

唯一脱敏规则源为 `docs/security/data-classification.md`，后端字段输出与日志复用对应策略。公开：不含个人信息的静态说明；内部：题库、试卷、统计；敏感：标准答案、答卷内容；个人信息：姓名、手机号、头像、账号标识；机密：密码散列、令牌、签名密钥。密码、散列和签名密钥永不输出；令牌只允许认证成功时按 CS04 向本人下发，普通业务响应和全部日志不得包含。

手机号默认保留前三后四位，中间掩码；姓名在管理员资料页与本人页按最小必要显示，通用日志省略。答卷是业务上需要返回的敏感内容，明确归属授权例外，避免“敏感字段一律不响应”与产品功能冲突；不得因此将答案写入通用日志。

环境变量从部署密钥管理注入，不提交 `.env` 实值，样例只写键名；先检查 `.gitignore` 再引入实现。轮换流程：撤销泄露值、生成替换值、注入各环境、滚动或蓝绿切换、失效相关会话、验证旧值拒绝、扫描历史与镜像、归档事件。扫描报告只存指纹和位置。

### 5. 供应链与适用性

许可证和版本清单纳入 CI，扫描包括传递依赖和最终镜像，阈值与修复时限按 SG03。离线功能测试不需要外部网络；漏洞源更新是独立门禁步骤，离线无法取得有效扫描不能冒充发布通过。

AI 十项全部登记当前不适用，原因是未引入模型、检索或工具；仍按 SG04 把题干和答案作为不可信数据。未来引入 AI 必须先更新规格：规则负责可确定计分；模型工具落既有授权服务；提示词随版本评审；锁定模型参数；统一超时退避；输出校验；无引用固定回复；正文放用户消息；正确／拒答评测；记录模型、提示词版本、耗时、用量和命中数而不记全文。

## Risks / Trade-offs

- [每请求读取会话有额外数据库成本] → 索引和连接池，容量测试验证；不以延迟撤销缓存换性能。
- [Strict Cookie 限制跨站前端] → 同站 HTTPS 网关部署，环境切换不改安全属性。
- [刷新重放与正常标签并发冲突] → 前端单次刷新协调并测试两个标签；保留服务端重放撤销策略。
- [原型不能证明浏览器令牌存放] → 以真实前端浏览器存储检查作为安全最终验收依赖。

## Migration Plan

先交付授权与字段清单，再建立会话表和安全中间件，最后与业务资源逐项接入；任何未完成接口保持默认拒绝。更新策略以版本化方式上线，令牌格式变化时撤销旧会话，回退必须保持失效记录；不得为回滚临时放宽安全策略。按 QA01–QA06 归档矩阵、攻击回归、扫描与轮换演练。
